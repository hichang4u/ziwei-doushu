> **이 문서는 한국어 포크의 안내입니다.**
> 원본 저장소는 [Renhuai123/ziwei-doushu](https://github.com/Renhuai123/ziwei-doushu)이고, 이 포크([hichang4u/ziwei-doushu](https://github.com/hichang4u/ziwei-doushu))는 여기에 한국 출생 시간 처리와 한국어 화면을 더했습니다. 원본 프로젝트의 업데이트 기록과 상세 설명은 [중국어 README](./README.md)를 보세요.

**1. 프로젝트 이념**: 자미두수(紫微斗數)는 중국 전통 명리학의 보물이며, 니하이샤(倪海厦)는 『천기(天紀)』에서 정통 자미두수 체계를 정리했습니다. 기술을 통해 더 많은 사람이 이 학문을 접하고 배우기를 바랍니다.

배반 알고리즘과 지식 베이스를 공개하는 것은 **알고리즘은 공개된 전통의 지혜이며 담장 안에 가둬 둘 것이 아니라고** 믿기 때문입니다. 진짜 가치는 해석의 깊이, 다듬어진 사용자 경험, 그리고 꾸준한 운영으로 쌓이는 것에 있습니다.

**2. 프로젝트 정보**: <strong>니하이샤 『천기』</strong> 교학 체계에 기반한 자미두수 배반 시스템입니다. 완전한 배반 알고리즘, 사화(四化) 체계, 격국 지식 베이스, 고전 원문 데이터와 함께 전부 공개된 자미두수 해석 데이터를 담고 있습니다. **v4.0 해석 데이터셋은 명반 67.5만 개 × 13개 주제 = 해석 877만 단락, 본문 약 204억 자, 압축 해제 시 56.6 GB**입니다(2026-10-15 공개).

| 데이터셋 | 명반 | 해석 단락 | 압축 해제 | 수록 연도 | 명반당 해석 글자 수 |
|---|---|---|---|---|---|
| **v4.0 해석 데이터셋** (2026-10-15) | **674,976** | **8,774,688** | **56.6 GB** | **1950–2026** (실재하는 날짜만) | **약 3.0만 자** |
| v3.0 표본 데이터셋 | 518,400 | 6,739,200 | 33.1 GB | 1924–1983 | 약 2.1만 자 |
| 변화 | +30% | +30% | **+71%** | +17년 | +44% |

원본 프로젝트의 온라인 서비스: [metisziwei.com](https://metisziwei.com/?from=gh-readme) (중국어)

> **참고: 육친(六親) 판단에 대하여**
>
> 자미두수는 육친(부모·형제·자녀 등)을 판단하는 데 한계가 있습니다. 니하이샤는 『천기』에서 "두수로 육친을 보는 것은 본래 조금 약하다"고 말했습니다([2강 상 · 00:25:27](https://www.bilibili.com/video/BV1KJsLekEfA?p=3&t=1527)). 전통 술수 가운데 철판신수(鐵板神數)는 육친을 맞춰 보는 데 나름의 강점이 있습니다([2강 상 · 00:03:15](https://www.bilibili.com/video/BV1KJsLekEfA?p=3&t=195)). 그럼에도 니하이샤가 자미두수를 중심에 둔 것은, 지리·환경·인사(人事)를 함께 보며 "위로 천문, 아래로 지리, 가운데로 인사를 아는" 완전한 체계를 이루기 때문입니다([2강 상 · 00:25:43](https://www.bilibili.com/video/BV1KJsLekEfA?p=3&t=1543)). 따라서 육친에 관한 분석은 참고용으로만 보세요.

## 이 포크에서 추가한 것

| 영역 | 내용 |
|---|---|
| **한국 출생 시간** | 서울의 과거 표준시 변경과 서머타임(1908–1911·1954–1961 UTC+8:30, 1955–1960 여름 UTC+9:30, 1948–1951·1987–1988 여름 UTC+10)을 IANA `Asia/Seoul` 데이터로 반영합니다 (`lib/ziwei/tz-kr.ts`) |
| **두 가지 처리 방식** | 진태양시(출생 당시 실제 오프셋 + 경도 + 균시차)와 KST 시각(과거 오프셋만 +9 기준으로 환산, 경도 보정 없음) 중에서 고를 수 있습니다 |
| **서머타임 입력 해석** | 입력한 시각은 기본적으로 표준시로 봅니다. "당시 서머타임 시계 기준"에 체크할 때만 서머타임을 적용합니다. 서머타임 시작 때 존재하지 않는 시각은 오류로 알려 줍니다 |
| **한국 도시 경도** | 17개 시·도, 79개 시·군의 시청·군청 경도 (`lib/ziwei/cities-kr.ts`) |
| **한국어 화면** | **화면 왼쪽 아래의 「한국어」 버튼**으로 전환합니다. 용어는 `자미(紫微)` / `자미` / `紫微` 세 가지 표기 중에서 고릅니다. 별 70개·궁 12개 등 명반 용어 사전은 `lib/i18n/terms-ko.ts`에 있습니다 |
| **해석 화면 연결** | 원본에 있었지만 화면에 연결되지 않았던 격국 판정 카드(`PatternsCard`)와 별 상세 패널(`StarDetailPanel`)을 `/chart`에 붙이고 한국어로 옮겼습니다. AI API 없이도 볼 수 있습니다 |
| **AI 해석 프롬프트** | 한국어 화면에서는 한국어로 답하라는 프롬프트를 보내고, 요청에 `locale`을 함께 실어 보냅니다 (`lib/i18n/prompts/`) |

한국어 화면에서도 엔진·격국 판정·공유 링크·기록은 중국어(간체) 용어를 그대로 키로 씁니다. 언어는 표시에만 영향을 줍니다.

## 엔진이 처리하는 것

| 기능 | 설명 |
|---|---|
| 진태양시 보정 | 출생지 경도와 균시차로 보정해, 시진 경계 근처에서 시진이 한 칸 틀리는 일을 막습니다. 보정으로 자정을 넘으면 날짜도 바꿉니다 |
| 중국 서머타임 | 1935–1991년 중국 대륙의 서머타임 기간을 판정합니다 (`dst-cn.ts`). 입력이 서머타임 시각인지 알 수 없으므로 자동으로 빼지 않습니다 |
| 윤달 | 네 가지 처리 방식(전반·후반 15일로 나눔 / 다음 달 / 그 달 / 윤달 그대로)을 엔진 옵션으로 고를 수 있습니다. 기본은 15일 기준으로 나누는 방식입니다 |
| 야자시(夜子時) | 23:00–23:59는 다음 날로, 00:00–00:59는 그날로 배반합니다. 엔진 옵션으로 바꿀 수 있습니다 |
| 별 밝기 | 묘(廟)·왕(旺)·득(得)·리(利)·평(平)·불(不)·함(陷) 7단계. 유파별 밝기 표 4종을 엔진 옵션으로 전환할 수 있습니다 |
| 사화 | 생년 사화를 배치합니다. 화면에서 대한·유년 사화를 겹쳐 볼 수 있습니다. 궁간 자화(自化)는 니하이샤 체계에 따라 넣지 않았습니다 |
| 12신 | 본명은 생년 지지로, 유년은 유년 지지로 일으킵니다 |
| 격국 판정 | `patterns.ts` 1,100여 줄, 40여 종 (군신경회·자부동궁·양량창록·살파랑·기월동량 등). 격국마다 필수·가점·파격 조건과 출처를 함께 냅니다 |

엔진 코드는 `lib/ziwei/`에 있고 진입점은 `algorithm.ts`의 `generateChart()`입니다. 입력은 **양력** 날짜와 **시진 번호 0–11**(자=0 … 해=11)이며, 시계 시각이 아닙니다. 시계 시각을 날짜와 시진으로 바꾸는 일은 `lib/ziwei/birth-time.ts`의 `resolveBirthTime()`이 맡습니다.

## 빠른 시작

```bash
git clone https://github.com/hichang4u/ziwei-doushu.git
cd ziwei-doushu
npm ci
npm run dev          # http://localhost:3000/chart 에서 배반 데모

npm run typecheck    # TypeScript 검사
npm test             # 회귀 테스트 (배반 엔진, 한국 시간대, 출생시각 변환, 한국어 화면)
```

**배반에는 API 키가 필요 없습니다.** 공개 버전에는 **백엔드 라우트가 없어서**, AI 해석(`/api/interpret`)과 궁합 분석(`/api/heming`)은 직접 구현하기 전까지 404를 돌려주고 화면에 그 사실을 안내합니다.

## 포함되지 않은 것

해석 데이터베이스(`lib/ziwei/db-analysis.ts`는 자리만 잡아 둔 구현), 원본 서비스의 AI 프롬프트, 모든 `/api/*` 백엔드 라우트, 회원·결제, 배포 설정.
